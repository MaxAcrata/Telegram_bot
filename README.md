# Telegram-бот «Управление заявками на материалы»

Telegram-бот для управления заявками на стройматериалы с хранением данных в SQLite и автоматической ежедневной отчётностью.

## Возможности

- **Добавление заявок** — 6-шаговый диалог: наименование материала, количество, единица, инициатор, объект, дополнительная информация
- **Загрузка фото** — прикрепление фотографий через кнопку «📎 Добавить фото» в сводке заявки
- **Подтверждение перед записью** — сводка с кнопками «Подтвердить» / «Добавить фото» / «Исправить» / «Отмена». При ошибке — черновик сохраняется, возможность повторить
- **Восстановление черновиков** — при рестарте бота незавершённые заявки восстанавливаются из БД; пользователю предлагается продолжить или начать заново
- **«Другое» для инициаторов и объектов** — ручной ввод, если значения нет в списке
- **Автоподстановка инициатора** — если пользователь привязал себя к имени, шаг выбора инициатора пропускается
- **Завершение заявок** — администратор отмечает заявки как выполненные (по одной или массово)
- **Смена статуса** — администратор меняет статус: Новая → Заказана → Доставлена → Выполнена
- **Уведомления** — при создании и завершении заявки: inline-кнопка «Открыть заявку #N», уведомление в общий чат и инициатору в ЛС
- **Раздел «Заявки»** — просмотр всех заявок с фильтрацией по статусу (Все / ⚪ Новые / 🟡 Заказанные / 🔵 Доставленные / 🟢 Выполненные) и пагинацией
- **Карточка заявки** — полная информация с действиями: сменить статус, посмотреть фото, удалить
- **Удаление заявки** — с подтверждением и записью в журнал аудита
- **Админ-дашборд** — сводка: новые, заказанные, доставленные, просроченные, выполненные сегодня, всего активных
- **Фильтр анализа** — перед отчётом администратор выбирает: «Актуальные» или «Выполненные» заявки
- **Кликабельные ссылки** — URL в дополнительной информации автоматически преобразуются в кликабельные ссылки
- **Ежедневный отчёт** — автоматическая отправка сводки по активным заявкам (по расписанию)
- **Ручной анализ** — администратор может запустить отчёт в любой момент
- **Роли** — разделение прав между администратором и обычным пользователем
- **Динамические списки** — инициаторы, объекты и единицы измерения загружаются из БД, настраиваются через админ-панель
- **Админ-панель** — управление справочниками (добавление, переименование, удаление), кнопки в строке, резервная копия, журнал действий, очистка БД
- **Привязка инициаторов** — обычные пользователи выбирают своё имя при первом запуске, получают ЛС-уведомления. Защита от перехвата чужого имени
- **Просроченные заявки** — отдельный раздел отчёта с группировкой по инициаторам
- **SOCKS5-прокси** — опциональная поддержка для сетей с блокировкой Telegram
- **Безопасность** — экранирование HTML, проверка прав доступа к заявкам и фото (IDOR-защита), атомарные операции изменения статуса, параметризованные SQL, rate limiting
- **CI/CD** — автоматический запуск flake8, black и pytest на каждый push через GitHub Actions

## Быстрый старт

### 1. Клонировать и установить зависимости

```bash
git clone <repo-url>
cd Telegramm_bot
python -m venv .venv
.venv\Scripts\activate       # Windows
pip install -r requirements.txt
```

### 2. Настроить переменные окружения

Создайте файл `.env`:

```env
TELEGRAM_BOT_TOKEN=ваш_токен_от_BotFather
TELEGRAM_CHAT_ID=ваш_chat_id
ADMIN_IDS=123456789,987654321

DB_PATH=bot.db

OVERDUE_DAYS=3
REPORT_HOUR=9
REPORT_MINUTE=0

# Прокси (опционально)
# SOCKS5_PROXY=socks5://127.0.0.1:1080
```

### 3. Запустить бота

```bash
python bot.py
```

База данных `bot.db` создаётся автоматически при первом запуске. Справочники (инициаторы, объекты, единицы измерения) заполняются значениями по умолчанию.

| Кнопка / Команда | Кто видит | Описание |
|---|---|---|
| `/start` | Все | Главное меню / регистрация (для новых пользователей) |
| `📋 Заявки` | Админ | Все заявки с фильтрами по статусу и пагинацией |
| `📊 Дашборд` | Админ | Сводка: новые, заказанные, просроченные, выполненные сегодня |
| `➕ Добавить заявку` | Все | Запуск диалога добавления заявки |
| `📊 Анализ` | Админ | Выбор фильтра и запуск отчёта |
| `✅ Завершить заявку` | Админ | Выбор и завершение активной заявки (с комментарием) |
| `📋 Мои заявки` | Все | Заявки текущего пользователя с поиском |
| `⚙️ Настройки` | Админ | Управление справочниками, кнопками, backup, журнал |
| `⛔ Выход` | Все | Возврат к кнопке `/start` |
| `❌ Отмена` | Все | Отмена текущего диалога (на любом шаге) |

## Диалог добавления заявки

```
При наличии черновика → предложение «Продолжить» / «Новая заявка»
Шаг 1/6 → Наименование материала или товара
Шаг 2/6 → Количество (число)
Шаг 3/6 → Единица (кнопки из БД)
Шаг 4/6 → Инициатор (кнопки из БД / автоподстановка)
Шаг 5/6 → Объект (кнопки из БД / «Другое»)
Шаг 6/6 → Дополнительная информация (ссылки допустимы, или «-» для пропуска)
Подтверждение → ✅ Подтвердить / 📎 Добавить фото / ✏️ Исправить / ❌ Отмена
```

Если пользователь привязан к инициатору, шаг 4 пропускается автоматически. Кнопка «Исправить» возвращает к шагу 1 с сохранёнными данными. Кнопка «📎 Добавить фото» позволяет прикрепить фотографии к заявке.

## Раздел «Заявки» (админ)

Просмотр всех заявок с возможностью:
- **Фильтрация по статусу**: Все / ⚪ Новые / 🟡 Заказанные / 🔵 Доставленные / 🟢 Выполненные
- **Пагинация** по 8 заявок на страницу
- **Карточка заявки** при нажатии — все поля + действия:
  - 🔄 Сменить статус
  - 📷 Посмотреть фото
  - 🗑 Удалить (с подтверждением)
  - ⬅️ Назад к списку

## Просмотр фото в отчёте

При анализе заявок в отчёте отображается метка `📎 Фото: N шт.` для заявок с фото. Кнопки `📋 #N Детали 📎` — нажатие показывает карточку заявки с возможностью просмотра фото.

## Уведомления

При создании заявки:
1. Пользователю — подтверждение с номером заявки
2. В общий чат — уведомление с inline-кнопкой «Открыть заявку #N»

При завершении заявки:
1. Администратору — inline-сообщение с кнопкой «Открыть заявку #N»
2. В общий чат (`TELEGRAM_CHAT_ID`)
3. Инициатору в ЛС (если привязан к Telegram)

## Регистрация инициатора

При первом запуске `/start` обычному пользователю предлагается выбрать своё имя из справочника. Если имя уже привязано к другому пользователю — регистрация отклоняется. После привязки:
- Имя инициатора подставляется автоматически при создании заявки
- Пользователь получает уведомления о выполнении своих заявок в ЛС

## Админ-панель

Администратор может управлять через `⚙️ Настройки`:
- **Справочники**: добавлять, переименовывать, удалять значения (объекты, инициаторы, единицы)
- **Кнопки в строке**: настраивать количество кнопок в строке клавиатуры (1–6) для каждого справочника
- **💾 Резервная копия**: создание и проверка целостности резервной копии БД
- **📋 Журнал действий**: последние действия (создание, завершение, редактирование, смена статуса, удаление)
- **🗑 Очистить БД**: удаление всех заявок (автоматический backup перед очисткой)

## Статусы заявок

| Эмодзи | Статус | Описание |
|---|---|---|
| ⚪ | Новая | Новая заявка |
| 🟡 | Заказана | Отмечена как заказанная |
| 🔵 | Доставлена | Отмечена как доставленная |
| 🟢 | Выполнена | Завершена администратором |
| 📦 | Архив | Архивирована автоматически (ежедневно в 03:00, старше 90 дней) |
| 🔴 | — | Просрочена (более `OVERDUE_DAYS` дней, отображается в отчёте) |

## Тесты

```bash
pip install -r requirements.txt
pip install flake8 "black==26.5.1" pytest pytest-asyncio

# Запуск тестов
python -m pytest tests/ -v

# Проверка линтеров
flake8 . --count --select=E9,F63,F7,F82 --show-source --statistics
black --check --diff .
```

## CI/CD

При каждом push в `main` GitHub Actions автоматически запускает:
- **flake8** — проверка на критические ошибки (E9, F63, F7, F82)
- **black** — проверка форматирования (`black==26.5.1`)
- **pytest** — запуск всех тестов

## Переменные окружения

| Переменная | Обязательная | По умолчанию | Описание |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Да | — | Токен бота от @BotFather |
| `TELEGRAM_CHAT_ID` | Да | — | ID чата для отправки отчётов и уведомлений |
| `ADMIN_IDS` | Нет | `""` | Telegram ID администраторов через запятую (нечисловые значения пропускаются) |
| `DB_PATH` | Нет | `/data/bot.db` (cloud) / `bot.db` (local) | Путь к файлу SQLite базы данных |
| `OVERDUE_DAYS` | Нет | `3` | Дней до просрочки заявки |
| `REPORT_HOUR` | Нет | `9` | Час отправки ежедневного отчёта |
| `REPORT_MINUTE` | Нет | `0` | Минута отправки отчёта |
| `REPORT_TIMEZONE` | Нет | `""` (UTC) | Часовой пояс для расписания (IANA, например `Europe/Moscow`) |
| `SOCKS5_PROXY` | Нет | `""` | Адрес SOCKS5-прокси (например `socks5://127.0.0.1:1080`) |
| `RATE_LIMIT_REQUESTS` | Нет | `5` | Максимум запросов в окно rate limiting |
| `RATE_LIMIT_WINDOW_SEC` | Нет | `60` | Окно rate limiting (секунды) |
| `MAX_FIELD_LENGTH` | Нет | `500` | Максимальная длина текстовых полей |
| `MAX_PHOTOS_PER_REQUEST` | Нет | `5` | Максимум фото к одной заявке |
| `BACKUP_DIR` | Нет | `/data/backups` (cloud) / `backups` (local) | Директория для резервных копий |
